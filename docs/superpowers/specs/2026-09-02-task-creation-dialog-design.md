# 新建任务弹窗与演示任务重置设计

## 目标

让用户不依赖 Swagger，直接在任务看板中创建多个不同任务，并清楚填写任务级 L1 参数、任务组 L2 参数和每个步骤的 L3 参数。同时消除“创建演示任务”重复点击却没有新增任务的歧义。

## 交互方案

看板顶部增加“新建任务”按钮。点击后打开模态弹窗，表单包含：

- 任务组名称。
- 任务名称。
- L1 基础参数 JSON。
- L2 组级覆盖 JSON。
- 一个或多个步骤。
- 每个步骤的名称和 L3 覆盖 JSON。
- 添加步骤、删除步骤、取消和创建按钮。

表单默认提供两个步骤。JSON 输入框默认值为 `{}`，并在提交前由浏览器解析和校验。空内容按 `{}` 处理；非 JSON 对象、JSON 语法错误、空任务名、空组名、空步骤名或没有步骤时，阻止提交并在弹窗内显示中文错误。

创建成功后关闭弹窗、清空表单、刷新任务列表，并显示新任务 ID。创建失败时保留用户输入，展示后端返回的错误，例如组名重复。

## 演示任务行为

原“创建演示任务”按钮改名为“重置演示任务”。点击后：

1. 后端锁定并查找固定演示任务组。
2. 如果已存在，删除该任务组以及级联关联的任务、步骤和日志。
3. 重新创建处于 `pending` 状态的三步演示任务。
4. 返回 HTTP `201` 和新的任务数据。

这样无论演示任务当前是 `pending`、`running`、`done` 还是 `failed`，点击一次都能恢复到可重新演示的初始状态。

## 前端结构

弹窗直接放在 `app/static/index.html` 中，通过原生 JavaScript 控制显示和关闭，不引入新的前端框架或构建工具。

每个步骤使用一行编辑区域，包含步骤名称、L3 JSON 文本框和删除图标按钮。删除按钮至少保留一个步骤；添加步骤在列表底部追加空步骤。

弹窗使用固定最大宽度和内部滚动，保证多步骤表单在桌面和移动端都不会溢出视口。弹窗打开时按 Escape 可关闭，点击遮罩可关闭，提交期间禁用创建按钮，避免重复提交。

## 后端与数据流

新建任务继续复用现有 `POST /api/tasks`，不增加重复接口。

前端将表单转换为：

```json
{
  "group_name": "华东客户组",
  "group_overrides": {"channel": "email"},
  "name": "新品通知任务",
  "base_parameters": {"tone": "formal", "retry": 1},
  "steps": [
    {"name": "准备消息", "overrides": {"tone": "friendly"}},
    {"name": "发送消息", "overrides": {"tone": "", "retry": 3}}
  ]
}
```

演示重置继续使用 `POST /api/demo/seed`，但语义从“存在则复用”修改为“删除旧演示数据并重建”。删除和创建必须在一次事务中完成，避免只删除未重建的中间状态。

## 错误处理

- 前端 JSON 解析失败：不发送请求，指出具体字段。
- 参数值不是 JSON 对象：不发送请求。
- 输入校验失败：使用弹窗内错误区展示。
- 重复任务组名称：后端返回 `409`，保留表单输入。
- 网络或服务异常：显示请求失败信息，允许用户重试。
- 重置演示任务失败：旧任务和新任务修改全部回滚。

## 测试

后端集成测试：

- 首次重置创建演示任务并返回 `201`。
- 已完成的演示任务再次重置后得到新的任务 ID、`pending` 状态、当前步骤 0、日志数 0。
- 重置操作后数据库中只有一个演示任务组和一个演示任务。

前端静态测试：

- 页面包含“新建任务”和“重置演示任务”。
- 页面包含任务表单、步骤列表、添加步骤和创建按钮。
- JavaScript 包含 JSON 对象校验、动态步骤和提交 `/api/tasks` 的逻辑。

浏览器端到端测试：

1. 打开弹窗。
2. 创建一个两步任务。
3. 再创建一个不同组名的三步任务。
4. 确认列表同时显示两个任务。
5. 输入非法 JSON，确认页面阻止提交。
6. 完成演示任务后点击重置，确认重新得到 pending 任务。

## 验收标准

- 用户能在看板直接创建多个任务。
- 每个任务至少一个步骤，步骤可动态增删。
- L1、L2、L3 参数都能通过 JSON 输入。
- 非法 JSON 不会发送到后端。
- 创建成功后任务立即出现在列表中。
- 演示任务每次重置后都回到全新的 pending 状态。
- 现有参数、认领、完成和并发测试继续通过。
